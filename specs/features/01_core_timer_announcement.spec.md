## 1. 🎯 概述与业务目标 (Overview & Objectives)

### 1.1 背景与痛点
手机用户在进行学习、工作、冥想或轻度小憩时，通常需要时间感知，但传统闹钟的声音侵入性过强（强提醒引起心率骤升），普通倒计时器又无法在过程中感知时间流逝。
SnoozeDD 核心 MVP 提供一种“温和不打扰的伴随式计时体验”，通过自定义时间节点与温柔语音播报，帮助用户无压力掌控时间。

### 1.2 核心目标 (Goals)
- [ ] 支持正向计时与倒计时模式，主界面直观呈现时间进度。
- [ ] 支持用户在单次计时中预设 1~N 个中间时间节点（Checkpoints）。
- [ ] 时间节点触发时，自动调用原生语音（TTS）或轻柔铃音执行弱提醒播报，不阻断手机当前进行的其他事务。
- [ ] 在手机锁屏或切换到后台时，计时与到点播报功能依然能够精准稳定触发。

### 1.3 非目标 (Non-Goals)
- 本次 MVP **不包含**用户账号注册与登录。
- 本次 MVP **不包含**多端云端数据同步。
- 本次 MVP **不包含**复杂的日历与待办事项系统关联。

## 2. 🚧 需求范围与边界 (Scope Boundaries)

### 2.1 包含范围 (In-Scope)
1. **计时控制模块**：
   - 设置倒计时时长（时/分/秒）。
   - 开始、暂停、继续、重置/停止。
2. **多节点播报配置模块**：
   - 动态增、删、改、查提醒节点。
   - 配置节点的触发时机（例如：“剩余 15 分钟”、“已进行 30 分钟”）。
   - 配置节点的自定义播报文案（例如：“还剩十五分钟，请放缓呼吸”）。
3. **语音播报引擎 (TTS)**：
   - 手机系统内置离线 TTS 语音朗读。
   - 弱提醒音频机制（播放时轻微闪避背景音乐，播报完毕恢复）。
4. **后台运行与防杀保障**：
   - 锁屏状态下后台保活与精准到秒触发。
5. **本地配置持久化**：
   - 保存用户上一次的计时时长与节点配置，下次启动自动恢复。

### 2.2 不包含范围 (Out-of-Scope)
- 不支持云端备份。
- 不支持在线 AI 生成拟真声音模型（MVP 仅使用手机本地离线原生 TTS）。
- 不支持强提醒锁屏全屏强弹窗（违背“弱提醒”核心定位）。

## 3. 👥 用户角色与场景用例 (User Stories)

| 角色 | 期望操作 | 达成价值 |
| :--- | :--- | :--- |
| 专注工作者 | 设定 45 分钟番茄钟，并在剩余 10 分钟时听到“还有十分钟进入收尾” | 无需低头看手机屏幕即可感知时间节奏 |
| 小憩休息者 | 设定 20 分钟小憩，在第 15 分钟听到轻柔提示音唤醒浅睡眠 | 避免被高分贝刺耳闹钟吓醒 |
| 演讲备考者 | 设定 12 分钟模拟计时，在第 5 分钟和第 10 分钟播报节点提示 | 训练阶段性演讲时间把控能力 |

## 4. 🛠 技术约束与移动端规范 (Technical Constraints)

- **支持平台**：Android 8.0+ 与 iOS 14.0+
- **网络需求**：100% 离线运行，无需外网权限
- **权限申请范围**：
  - 音频播放权限 (Background Audio)
  - 电池优化白名单申请引导 (针对 Android 杀后台机制)
  - 屏幕常亮权限 (WakeLock，仅在前台且用户开启时生效)

## 5. 🗄 数据结构与状态契约 (Data Contracts)

```typescript
// 播报时间节点数据结构
export interface CheckpointModel {
  id: string;                     // 唯一标识
  offsetSeconds: number;          // 距离开始或结束的秒数
  type: 'remaining' | 'elapsed';  // remaining: 剩余X秒触发; elapsed: 已过去X秒触发
  text: string;                   // 播报文字
  chimeSound: string;             // 伴随音效 (如: 'gentle_bell', 'water_drop', 'none')
  enabled: boolean;               // 是否启用
}

// 计时配置模型
export interface TimerConfigModel {
  id: string;
  name: string;
  totalSeconds: number;
  checkpoints: CheckpointModel[];
  keepScreenAwake: boolean;
  volume: number;                 // 0.0 ~ 1.0
}
```

## 6. 📋 核心业务规则 (Business Rules)

1. **节点冲突判定**：同一秒数偏移量不可重复触发多个不同的播报，系统在保存时进行时间唯一性去重校验。
2. **播报队列保护**：若前一个播报尚未朗读完毕即迎来下一个节点，采用阻塞队列依次朗读，避免音频并发冲突。
3. **后台时间校准**：应用从后台唤醒或用户中途解锁屏幕时，系统必须使用物理时间差 `DateTime.now().difference(startTime)` 重新校准当前秒数，绝对禁止单纯依赖 `Timer.periodic` 的步长累加（防止系统休眠时定时器冻结导致的时钟漂移）。
4. **音频弱提醒策略**：播报前调低背景多媒体音量（Audio Ducking），朗读音量适中，结束后恢复。

## 7. ✅ 验收标准与测试用例 (Acceptance Criteria)

- [ ] **场景 1：倒计时多节点正常播报**
  - **Given**：设置 60 秒倒计时，在剩余 30 秒设置播报文案“半分钟已过”
  - **When**：启动计时，秒数倒计至 30 秒时
  - **Then**：系统正常播放提示音并朗读该文案，计时继续前进至 0 秒后触发结束。
- [ ] **场景 2：手机锁屏后台保活播报**
  - **Given**：设置 3 分钟倒计时并在 1 分钟后触发播报
  - **When**：启动倒计时后立即按下手机电源键锁屏
  - **Then**：在手机黑屏状态下，到第 1 分钟时仍能听到清晰柔和的语音播报。
- [ ] **场景 3：节点增删与本地持久化**
  - **Given**：用户新增了 3 个自定义时间节点并修改了播报文案
  - **When**：杀死应用进程重新打开
  - **Then**：之前配置的节点与文案完整展示，无数据丢失。
